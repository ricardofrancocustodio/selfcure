Self-healing Playwright tests · BYOK · open source

Selfcure cures tests,
not components.

Crawl your frontend, generate Playwright tests with the LLM of your choice, and let selfcure auto-patch flaky locators. When the test is fine but the component is broken, selfcure tells you.

Selfcure distinguishes a bad test from a bad component. It patches the test when the locator drifts. When the component has no stable identifier, it tells you — and refuses to paper over a frontend bug. — design principle, since v0.1

Pipeline

How it works

A single command runs the whole pipeline. Each stage is its own npm workspace package — pick and choose.

01 · CRAWL

Read your source

Static AST via @typescript-eslint/parser + dynamic DOM capture via Playwright codegen. Outputs a structured component map.

02 · GENERATE

LLM writes the tests

Component analysis + interactive-element map go to the LLM. Returns one ready-to-run .spec.ts per component.

03 · HEAL

Patch on failure

Failures get classified. Locator drift → ask LLM for a diff, sanity-check, apply, retry. Component-level bugs → flagged for human review.

Capabilities

What you get

Multi-provider BYOK

Anthropic, OpenAI, Google Gemini, Groq, DeepSeek, or local Ollama. Swap providers with one config line. No vendor lock-in.

Self-healing loop

Failed locator? selfcure asks the LLM for a unified diff, applies it under a parse sanity check, and rolls back on failure. Max attempts configurable.

Testability score

Every component gets a 0–100 score. Low score? You learn that the FE needs data-testid — not that "tests are flaky."

Browser-based init selfcure web

Open a wizard at localhost:3333. Auto-detects which provider keys you've already exported. Picks ./src, ./app, etc. from your project.

Playwright-native

Generated tests are plain @playwright/test code. No proprietary runner, no lock-in. Trace + screenshot on every failure.

HTML report

Per-test status, applied diffs (collapsible), and a "Components needing FE intervention" section that calls out unfixable items.

Get going

Quick start

selfcure is pre-publish — install from source while we stabilise the API.

1 · Link the CLI from source

# Clone and build
git clone https://github.com/ricardofrancocustodio/selfcure.git
cd selfcure
npm install
npm run build

# Register the binary globally (symlink, so rebuilds reflect automatically)
cd packages/cli
npm link

2 · Configure in your target project

# From your frontend project's root
cd ~/path/to/your-app
selfcure web        # browser wizard at http://localhost:3333
# or
selfcure init       # terminal wizard

The wizard detects which provider keys you already have exported in your shell and pre-selects them. Picks Anthropic / OpenAI / Gemini / Groq / DeepSeek / Ollama from a dropdown.

3 · Run

# Start your dev server in another terminal first
npm run dev

# Then in your-app root
selfcure crawl ./src    # sanity-check the crawler
selfcure run            # full pipeline: crawl → generate → run → heal → report

Status

Where it stands

selfcure is at v0.1.0 — a working monorepo with the full pipeline scaffolded and the LLM provider layer in place. The crawl / analyze / generate / run / heal / report stages are wired end-to-end; some stages still have placeholder logic while the AI integration is hardened.

Best place to follow progress, file issues, or contribute is the GitHub repo. Stars help; PRs help more.
