Platform

Built for frontend teams, not one-off QA scripts.

selfcure gives platform, QA, and frontend leads a shared source of truth for testability before automation tools, CI jobs, or human QA spend time on unstable surfaces.

Governance

WCAG Accessibility Audit

Static analysis for 10+ WCAG rules including labels, names, and focus order. Ensure compliance before design intent becomes component debt.

Scale

Monorepo-native analysis

Scan React, Vue, Angular, and HTML across apps, packages, design systems, and shared component libraries.

Automation

PRs with frontend ownership

Route deterministic data-testid fixes through standard code review so QA pipelines do not mask component debt.

AI ready

MCP server for agent workflows

Expose lint, component lists, selector analysis, and test-id suggestions to Claude Desktop, Cursor, VS Code, Windsurf, and other MCP clients.

Governance

Tag Maturity Level (TML)

Standardized maturity model for every tag. Explains why an element is hard to test and what exactly needs to change to reach professional automation standards.

Visibility

Test ID Inventory

Govern your data-testid contract across the organization. Scan for actual usage and audit it against naming conventions and stability requirements.

No API key

Works without an LLM key

For corporate Copilot or Cursor seats with no API key access: selfcure never asks for one. Copy prompt to IDE generates a ready-made data-testid fix prompt your team pastes into the agent they already run — the key stays in the enterprise, never in selfcure.

Trend

Maturity over time

Every scan records a snapshot, so leaders see testability score and governed-tag coverage trending across releases — evidence the frontend is getting more automatable, not just a point-in-time number.

Security posture

Local-first, no code leaves your network.

Source analysis runs on your machine. Repository auth is delegated to your existing SCM provider. Every automated fix goes through a normal pull request — nothing mutates production directly.

Local-first analysis OAuth scoped auth Audit logs Reviewable PRs only

What’s true today

  • Local-first source analysis — no mandatory cloud code upload.
  • GitHub, GitLab, and Bitbucket flows through scoped OAuth or local CLI auth (gh / glab).
  • WCAG accessibility compliance gates and reporting.
  • Reviewable pull requests instead of direct production mutations.
  • Policy thresholds configurable for CI, release gates, and platform scorecards.
